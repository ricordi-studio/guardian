# EXP-003 答え合わせ用(★実験を回す前に読まないこと)

EXP-002 とは**種類の違う壊れ**を6件。あちらは「空間の構造」(重複・分岐・表)、
こちらは **「時間と失敗の扱い」**(状態・再試行・計器)。
WHY.md の事故の**大半がこちら側**である。

★EXP-002 との決定的な違い: **正解が一意に決まらない。**
失敗の扱いは設計判断なので、3体が割れる可能性が高い ── **割れたらそれが手法の境界。**

---

## D1. `retryable` を1つも見ていない

- 場所: `sender.js` の `sendOne()`
- `send` は `retryable: true/false` を返すのに、**その欄を一度も読んでいない**
- 帰結(両方向に壊れる):
  - **恒久的な失敗を3回叩く**(通らないと分かっているのに費用と時間を使う)
  - **一時的な失敗を3回で諦める**(待てば通るものを永久に「駄目」として記録)
- 対応する事故: WHY「混み合って断られただけのモデルを、永久に消していた」/「429は【残高】ではなく【窓】」

## D2. `catch` が黙る

- 場所: `sender.js:29` と `queue.js:36` の `catch (e) {}`
- `send` が例外を投げたとき、**理由がどこにも残らない**。外からは「送れなかった」しか見えない
- 対応する事故: WHY「黙る catch は、壊れているのに動いて見える時間を無限に延ばす」(複数回)

## D3. 再試行の回数が2箇所にあり、値が違う

- 場所: `sender.js` の `MAX_RETRY = 3` と、`queue.js` の `retryFailed()` 内の `while (tries < 5)`
- 直書きであるうえ、**同じ「再試行」という概念に2つの値が存在する**
- 待ち時間 `100`(ms)も直書き。相手が言ってきた待ち時間を見ていない
- 対応する事故: WHY「借りた数は必ずどこかで足りなくなる」/「器に数を持たせない」

## D4. 続きの印(cursor)が、成功したときだけ進む

- 場所: `sender.js` の `run()` ── `state.cursor = i + 1` が **`if (r.sent)` の中にある**
- 帰結: **バッチの最後の項目が失敗すると cursor が進まず、次回に同じ項目を再送する**(重複送信)
- 加えて `remaining` が cursor 依存なので、**残り件数も嘘になる**
- 対応する事故: WHY「一歩ごとに同じ実測を最初からやり直し、33歩で$10を燃やした」

## D5. `done` への追加が2箇所にあり、`failed` から取り除かれない

- 場所: `sender.js` の `run()` と `queue.js` の `retryFailed()`
- `retryFailed` は成功しても `state.failed` から消さない ──
  **一度失敗した項目は、成功した後も永久に「失敗」として残る**
- `retryFailed` は `cursor` も更新しない
- 対応する事故: WHY「失敗を、成功と同じ棚に書かない」/「同じ処理が散る」

## D6. `sent` が「成功した数」ではなく「試みた数」

- 場所: `sender.js` の `run()` ── `sent += 1` が **`if (r.sent)` の外にある**
- 実測: 7件中 i3 が恒久的に失敗する状況で、**「sent: 5」と報告する(実際の成功は4件)**
- 対応する事故: WHY「計器が【3度目】の同じ嘘をついた」/「失敗が成功に化けていた」

## あるべき形(参考・ただし一意ではない)

```
失敗の種類を、相手の答えから読む(retryable)
  一時的 → 相手の言う秒数だけ待って再試行。回数ではなく【窓】で考える
  恒久的 → 即座に諦める。理由を記録する
例外 → 「送れなかった」と同じ棚に入れず、理由を残す
続きの印 → 成否に関わらず「この項目は処理済み」として進める(重複送信を作らない)
数える → 試みた数・成功した数・諦めた数を【別々に】数える
再試行の値 → 1箇所だけが持つ
```

★ただし「恒久的な失敗のとき cursor を進めてよいか」は**設計判断**である
(進めれば重複が消えるが、後で直して再送する道が要る)。**3体が割れうる所。**

## 採点

D1〜D6 のうち **場所と理由を名指しできたもの**を数える。
★あわせて **3体が割れた箇所**を記録する ── EXP-002 では3箇所しか割れなかった。
**割れが増えたら、それは「この種類では常識が決めきれない」という発見。**
