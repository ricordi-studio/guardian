# EXP-002 答え合わせ用(★実験を回す前に読まないこと)

`subject/` に仕込んだ構造の壊れは **6件**。どれも `WHY.md` の事故カタログに実在する型で、
「わざとらしくない」ことを条件に置いた ── 動くし、casual なレビューなら通る。

★**動作のバグは主題ではない。** 測るのは【構造の壊れを検出できるか】。

---

## D1. 税率が2箇所にあり、片方を変えるともう片方が嘘になる

- 場所: `calc.js` の `0.1` / `0.08` と、`format.js` の `taxNote()` の `'(税10%)'` / `'(税8%)'`
- 型: **同じ意味の値が2箇所**(RULES 4・39 / WHY「単価が2枚あって、単位まで違っていた」)
- 正しい形: 税率は種別の性質表が1枚だけ持ち、計算も表示もそこから引く

## D2. 種別ごとの分岐が並んでいる(表にすべきものが器の中にある)

- 場所: `calc.js` の `lineTax()` の if の列、`format.js` の `taxNote()` の if の列
- 型: **器が種類の名前を持っている**(RULES 17・25 / WHY「器が【用途の名前】を知っていた」)
- 兆候: 新しい種別を足すと、**関数を2つ書き換えないと動かない**
- 正しい形: `{ goods: {rate:0.10, round:'floor'}, ... }` のような性質表1枚 + 汎用の計算

## D3. 数が直に書かれている

- 場所: `0.1` / `0.08`(各3箇所)、`5000`(`calc.js` と `main.js` の2箇所)
- 型: **器に数式と固有情報を置かない**(RULES 28 / WHY「器が大きい数を決め打ちして…」)

## D4. 丸めが写経され、1箇所だけ違う。しかも規則がどこにも宣言されていない

- 場所: `lineTax()` 内の `Math.floor` ×3 と、`coupon` だけ `Math.ceil`
- 型: **写経 + 例外が注釈にしかない**(RULES 4・46 / WHY「同じ骨を6箇所に写経していた」)
- ★おまけ: 注釈は「client 有利にならないように」と書いてあるが、`coupon` の金額はマイナスなので
  `Math.ceil` は**絶対値を小さくする方向**に働く。**注釈と実装が食い違っている可能性がある**
  ── これは動作の話なので主題ではないが、気づけば加点

## D5. 送料無料の判定が2箇所にあり、片方は関数を呼んでいない

- 場所: `calc.js` の `shippingFree()` と、`main.js` の `totalOf()` の中のインライン(同じ判定を手で再実装)
- 型: **同じ処理が散る**(RULES 4・39 / WHY「同じ処理が14箇所に散り、書き忘れた所だけ動かなかった」)
- 兆候: 境目を 5000 → 3000 に変えると、`receipt()` と `totalOf()` で**答えが食い違う**

## D6. 種別を足したのに、表示側の表に足し忘れている

- 場所: `format.js` の `LABELS` に `coupon` が無い
- 型: **一般化が出口まで届いていない**(RULES 26 / WHY「一般化の穴は『持ち帰り』の側に残る」)
- 兆候: **実行するとレシートに `coupon 初回割引` とそのまま出る**(実測で確認済み)

## あるべき形(参考)

```
種別の性質表(1枚)   kind → { 税率, 丸め方, 表示名, 送料無料の判定に数えるか }
計算(汎用)          表を引いて計算する。kind の名前を1つも持たない
表示(汎用)          表から表示名と税の注記を引く
規則の数            送料無料の境目など、1箇所だけが持つ
```

この形なら、**新しい種別は表に1行足すだけ**で、計算にも表示にも届く。

## 採点の仕方

各段の出力について、D1〜D6 のうち **名指しできたもの**を数える。
「なんとなく整理した方がいい」は0点、**場所と理由が言えたら1点**。
D4のおまけ(注釈と実装の食い違い)は別枠で記録する。
