# guardian — AIと一緒に直すための、壊れを見張る塊

> **まとめから読む → [METHOD.md](METHOD.md)**
> (バイブコーディングの弱点6つと、対策5層。個別の規律は RULES.md、由来は WHY.md)

**このフォルダごとコピーすれば、他のプロジェクトでも動きます。**

会話型AIと組んで開発すると、AIは**最小の読み込みで改修**します。
その結果、機能の接点が4層に散っていても1層だけ直され、**壊れた側は例外を出さない**。
これを機械で見張るための道具と、実際に事故を起こして手に入れた作法を1つにまとめたものです。

| ファイル | 中身 |
|---|---|
| **WHY.md** | **各検査が生まれた事故**。この塊の本体。検査を足したら必ず1行足す |
| **RULES.md** | 積み上げた作法(推測しない・数える・見えない失敗を作らない…)。AIに読ませる |
| `check.mjs` | 検査エンジン。**どのプロジェクトでも同じ中身**。外から他所も診られる |
| **`verdict.mjs`** | **合否**。宣言された証拠を集めて4語(通過/注意/**不明**/差戻)に落とす。**不明を緑に数えない** |
| `hooks/stop.js` | 「できました」と言い終える**手前**で合否を回す。差戻なら止める |
| `selfcheck.mjs` | **その検査エンジンを検査する**。わざと壊した見本で赤くなることを確かめる＋塊の健康診断 |
| `hooks/codemap.js` | 編集の**直前**に、触った実名で地図を引いて該当項を差し込む |
| `hooks/clock.js` | 毎ターン時刻を注入 + 監査の催促(**実装が変わったときだけ**) |
| `audit.md` | 定期監査の手順(4観点) |
| `templates/` | 地図・宣言・CLAUDE断片・フック登録の雛形 |
| `KIT_VERSION` / `CHANGELOG.md` | 配った版と変更の記録。配布先の番号と見比べて**どのコピーが古いか**を判断する |

## 入れ方 ── **このフォルダを置いて、AIに一言**

**人がやることは2つだけです。**

**① 塊を、相手のプロジェクトの `guardian/` に置く**

正本(GitHub)から取る ── PowerShell に貼る1行:

```powershell
gh repo clone ricordi-studio/guardian <相手のプロジェクトのフォルダ>\guardian; Remove-Item -Recurse -Force <相手のプロジェクトのフォルダ>\guardian\.git
```

手元の別プロジェクトからコピーしても構いませんが、**そのコピーが最新とは限りません** ──
正本から取るのが確実です(2度目からは下の `pull.mjs` が1行で済ませます)。
**② そのプロジェクトのAIに、こう言う**:

> **guardian/install.md を読んで導入して。**

これで終わりです。`install.mjs` を回すのも、宣言を書くのも、地図を書き始めるのも**AIの仕事** ──
人が手で置くファイルも、貼る作業もありません。

★一緒に運ばれるもの: **事故の記録(WHY.md)と作法(RULES.md)** ── これがこの塊の本体です。
  中身は元のプロジェクトで実際に起きた事故なので固有名が出ますが、**そのままで構いません**
  (「なぜこの検査があるか」は、具体的であるほど次の人に効く)。
  **エンジン(コード)だけは、どの現場へ持って行っても同じ中身**であることを自己検査が見張っています。

AIの中で起きること:

| 誰が | 何を |
|---|---|
| `install.mjs`(機械) | 地図の雛形を置く / **リポジトリを実際に見て**宣言の下地を書く / `.claude/settings.json` にフックを登録(**既存は壊さない**) / `CLAUDE.md` に読む順を追記 |
| AI(判断) | 「同じ意味の値が2箇所にある所」を探して宣言に書く / 触った機能から地図を書き始める / **わざと壊して落ちることを確かめる** |

### ★配った先の直りを、元へ還す(改善の還流)

実際に起きた(2026-08-28): 配布先で塊自身のバグが2つ見つかり、向こうで直された。
**だが元の塊には戻ってこなかった。**しかも両方の版が同じ番号のまま ── 版が嘘をついていた。
そのうち1つは「フォルダ名に空白があると壊れる」という、**元の現場では一生出ないバグ**だった。

**現場が増えると、こちらの現場では踏めない石を踏む。**それが配ることの見返りであり、
戻ってこなければ見返りを捨てている。**配ったものは、戻る道を用意するまで配り終えていない。**

#### 正本(GitHub)

**https://github.com/ricordi-studio/guardian** ── ここが唯一の正本。
配布先はここから取り、直したらここへ還す。

```bash
node guardian/pull.mjs           # 正本の最新を取り直す(1行)
node guardian/pull.mjs --check   # 取らずに、正本と何が違うかだけ見る
```

★`pull.mjs` は取り直す前に **この現場で塊を直していないか**を必ず見る。
  直していたら止まる ── 上書きすると、その現場の直りが黙って消えるから。
  先に `--report` で1枚を作り、正本へ渡してから取り直すこと。

#### 道具

```bash
node guardian/selfcheck.mjs           # 配られたときの中身のままか(ファイルごとに照合)
node guardian/selfcheck.mjs --report  # 直した分を【元の塊へ渡す1枚】にまとめる(配布先)
node guardian/selfcheck.mjs --stamp   # 意図した変更として指紋を押し直す(元の塊)
```

#### 流れ(人の承認を挟む)

| # | 誰が | 何を |
|---|---|---|
| 1 | 配布先のAI | 塊を直したら `selfcheck` が **どのファイルを直したか名指しで**赤くする |
| 2 | 配布先のAI | `--report` で `guardian-report.md` を作る(変わったファイルの中身+渡し方の説明) |
| 3 | **人** | その1枚を読んで**承認**し、元の塊のAIへ渡す(貼るだけ・ファイルを渡すだけ) |
| 4 | 元の塊のAI | 差分を読んで取り込む(**丸ごと上書きしない** ── こちらの改善が消えるため) |
| 5 | 元の塊のAI | `--stamp` → 版を上げて CHANGELOG に書く → **配った先へ配り直す** |

★**3(人の承認)を機械にさせない。**中身がそのまま外へ出るので、
  何を送るかは人が見て決める ── 自動送信にすると、送ってはいけないものが混ざる日が来る。

★報告は**丸ごとの中身**を出す(差分ではない)。配布先は元の塊を持っていないので差分が作れない。
  受け取る側は**AIが読んで判断する** ── 機械が丸ごと上書きすると、元の改善が黙って消える。

★指紋の対象は**エンジン(コードとフック)だけ**。
  WHY.md / RULES.md は配布先で事故が増えて当然なので数えない。

#### サーバーは要るか

**いまは要らない。**同じPCの別フォルダなら、上の1枚をコピーで運べば足りる。
サーバー(または git の共有リポジトリ)が要るのは、**別のPC・他人へ配るようになったとき**。
そのときも仕組みは変わらない ── 運ぶ手段が「コピー」から「送信」に変わるだけで、
**1〜5の流れと、3の人の承認はそのまま**。

## 使い方

```bash
node guardian/check.mjs                    # このリポジトリを検査
node guardian/check.mjs --tighten          # 口が減っていれば宣言の max を下げる(一方通行)
node guardian/selfcheck.mjs                # 塊そのものを検査(鍵もネットも要らない)
node guardian/verdict.mjs                  # 合否 ── 宣言した証拠を全部集めて4語に落とす
node guardian/verdict.mjs --fast           # 自足する証拠だけ(完了を名乗る手前・CI用)
node guardian/check.mjs --root ../other    # 他のリポジトリを外から検査(読むだけ)
node guardian/check.mjs --selectors a.html # 単発でセレクタだけ
```

CIに置くなら、出口コードが 1 になるのでそのまま落ちます。

## 夜中に回す(2段ある)

| | どこに置くか | コピーで付いてくるか |
|---|---|---|
| **①機械検査**(毎晩01:00) | `.github/workflows/guardian-nightly.yml` ← **install.mjs が置きます** | **○ 付いてくる** |
| **②観点を選んだ監査**(4観点) | **リポジトリの外**。AIの定期実行として登録する | **✗ 付いてこない** |

**①はクラウド(GitHub Actions)で回るので、PCの電源にもAIのセッションにも依存しません。**
赤くなったらIssueを立て、緑に戻ったら閉じます ── 見に行かなくても気づけます。

**②は人とAIの判断が要る**(重複・死にコード・メタ化余地を「実害か」で仕分ける)ので、機械にはできません。
ただし**回す手間はゼロに近づけてあります**。

- **誰でも1語で回せる**: `install.mjs` が `.claude/commands/guardian-audit.md` を置くので、
  そのリポジトリを開いた人は **`/guardian-audit`** と打つだけ(手順の正典は塊の中)
- **催促は自動**: `hooks/clock.js` が「前回から時間が経った**かつ**実装が変わった」ときだけ促す
- **完全に無人にしたいなら**、そのプロジェクトを対象にした定期実行をAI側に登録し、
  `guardian/audit.md` を読ませる(**アカウント側の設定なので塊には入れられません**)

## 外からできること / 中でしかできないこと

| | 外(パスを渡して診る) | 中(リポジトリに設置) |
|---|---|---|
| 記号の実在照合・不変条件・セレクタ | ◎ | ◎ |
| 毎晩の自動検査(CI) | ○ | ◎ |
| **編集の直前に地図を差し込む** | **✗ 不可能** | ◎ |
| **毎ターンの時刻注入・催促** | **✗ 不可能** | ◎ |

「編集の直前」を観測できるのは、**編集している主体(AIのランタイム)だけ**です。
ファイル監視では**書かれた後**にしか気づけず、MCPは**AIが呼びに来る道具**であって
こちらから押し込む口ではありません。

つまり **外 = 健康診断(事後に見つける) / 中 = 予防接種(事故の前に止める)**。
中に置くのが本筋で、外からの診断はおまけです。

## 配るときの約束

1. **失敗しても黙って通す。** フックが落ちると開発そのものが止まる
2. **プロジェクト固有のものを塊に入れない。** 他所で意味の無い催促・検査になる
3. **検査を足したら WHY.md に「どの事故を防ぐか」を書く**。種類(kind)を足したら `selfcheck.mjs` の見本にも足す
   ── 一度も試されていない種類があると、自己検査が落ちます
4. **配る前に `node guardian/selfcheck.mjs` を回す。**版・件数の嘘もここで捕まります
5. **双子のいない門を足さない。** 門は黙って死ねる。**同じ宣言を読む検査**が書いた後に落とすから、黙って通してよい
6. **誤検出を出さない。** 1件の誤検出が、検査全体の信用を殺す
