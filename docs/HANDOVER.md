### ⑦ `neighbors.mjs` に**余分な CR が1つ**あり、git の分類を左右している(9.17 の作業中に踏んだ)

230行目の末尾が `\r\r\n`(CRLF の手前にもう1つ CR)。これがあると git はこのファイルを
**バイナリ扱い**にしてバイト比較する。取り除くと**テキスト扱い**になり、`core.autocrlf=true` が
作業木を LF へ正規化して CRLF の blob と突き合わせるので、**全行が変わったこと**になる。

実測: 104行の変更が **1384行の書き換え**に見えた。CR を戻したら 104行に戻った。

★これは Guardian にとって他人事ではない ── **門は git の差分を読む**。
全行が変わったことになると全記号が「触れた」になり、近傍は `known` に吸われて **0件**になる。
**差分が膨らむと門は鳴らなくなる。**(いまは CR を戻してあるので鳴っている)
→ 直すなら「CR を消す」ではなく、`.gitattributes` で終端を決めるのが筋。**判断待ち。**
